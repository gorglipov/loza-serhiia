# LOZA: ручна передоплата на картку — підготовка Preview

Цей PR лише готує інструкції для добровільного ручного переказу у власному банківському застосунку покупця. LOZA **не списує гроші**, не підтверджує їх автоматично та не змінює наявні банківські інтеграції. Нових таблиць або міграцій D1 немає.

## Захист реквізитів

Номер картки **не можна записувати в GitHub, HTML, JS, D1, логах, Telegram або скриншотах**. Його вводить власник сам у Cloudflare Pages → проєкт LOZA → Settings → Variables and Secrets, окремо для потрібного середовища:

- `MANUAL_TRANSFER_CARD` — **Secret**: реальний номер картки отримувача без CVV/PIN/терміну дії;
- `MANUAL_TRANSFER_ENABLED` — звичайна змінна зі значенням `true` лише після перевірки всього сценарію і відповідності діяльності законодавству. За замовчуванням функція **вимкнена**.

Без обох змінних сайт не показує реквізити. Некоректний номер (довжина/контрольна сума), демо-замовлення чи старі замовлення без відомого способу оплати теж не показують їх.

## Що бачить покупець

1. Обирає повну передоплату або 100 грн передоплати + решта післяплатою.
2. Оформлює замовлення через перевірений Turnstile. Сервер рахує суми з D1.
3. Лише у відповіді на створення замовлення або його приватне відновлення за випадковим `Idempotency-Key` отримує реквізити, точну суму передоплати й номер замовлення.
4. Сам переходить у свій банк, переказує та повідомляє продавцю номер замовлення.

Публічні каталоги/конфігурація **не** повертають номер картки. Загальні API і логування не повинні додавати його. Після переказу статус оплати залишається `awaiting` до дій власника.

## Ручне підтвердження (вже є в PR #8)

Адмінпанель /admin → Замовлення → Деталі → Контроль надходження оплати:

1. `reported` — тільки якщо покупець повідомив про переказ; **не є оплатою**.
2. Власник перевіряє суму, отримувача й факт зарахування у власному банківському застосунку.
3. Лише потім `confirmed` із явним підтвердженням перевірки; інакше `awaiting` або `not_paid`.

Післяплата у Новій пошті лишається окремою відміткою/операцією і не стає сплаченою через статус передоплати. Історія змін — чинний журнал D1 з PR #8.

## Preview-перевірки перед будь-яким випуском

- У середовищі без змінних покупець не бачить реквізитів (не зупиняється замовлення).
- На **синтетичних даних**: для 300 грн — 100 грн передоплати й 200 грн післяплати, або повна передоплата 300 грн.
- Демо/некоректні замовлення — без реквізитів; повтор запиту не створює замовлення вдруге.
- /admin доступна лише власнику через Cloudflare Access; заборонено підтверджувати неотримані платежі.
- Перевірити стан Preview D1 і всі автоматичні тести. Не вводити дійсні платіжні реквізити в тестові скриншоти.
- **До окремого підтвердження власника не зливати PR і не ввімкнути Production-змінні**.
- Для регулярної онлайн-торгівлі перевірити необхідність державної реєстрації/оподаткування. Особистий переказ не є інтернет-еквайрингом і не замінює належне оформлення діяльності.

## Заміна/вимкнення

Негайно встановити `MANUAL_TRANSFER_ENABLED=false` у потрібному середовищі й опублікувати зміни конфігурації. За необхідності замінити/видалити `MANUAL_TRANSFER_CARD`; дані не були записані у репозиторій.
