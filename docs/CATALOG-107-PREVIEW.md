# Каталог LOZA: 107 сортів без фотографій

## Джерело й правила

Джерело — наданий власником PDF «Каталог лози винограду 2026–2027», 2 сторінки,
SHA-256 `94ef2e033480691a9b1162a5e825f48b0d5671a3a3936e2e165bddbeeb138a01`.
Рядки 1–107 містять сорти; рядки 108–110 порожні. Підтверджено точний збіг назв і
шести текстових характеристик із наявними 107 записами D1. Незалежну агрономічну
перевірку PDF не проводили; до перевірки власником картки так і позначені.

- Збережено смак, дозрівання, колір, вагу ягід, форму та морозостійкість.
- 84 ціни з колонки **«Лоза»** перенесено в копійки без округлення; 23 ціни відсутні.
  Колонка «Саджанець» порожня і не використовується.
- Позначку «Кишмиш» мають 28 сортів із явним маркером у PDF. Решта 79 — «без позначки»;
  відсутність маркера не подається як незалежне підтвердження наявності кісточок.
- Усі 107 реальних товарів видимі, зокрема без ціни: **«Немає в наявності»**.
- Фотографій, заглушок та вимоги завантажити фото немає.
- PDF не підтверджує актуальні залишки чи дозвіл продажу. Початкові нульові залишки
  збережено. Власник має явно підтвердити ціну, вказати залишок і дозволити продаж.
- Три демотовари архівовані, але їхні рядки й посилання зі старих замовлень залишаються.

Оригінальний знімок кожного рядка з номером сторінки/рядка зберігається в
`product_catalog.source_json`, а контрольна копія — в `server/catalog-source.json`.
Редагування та імпорт змінюють поточні дані, зберігаючи знімок джерела.

## Міграція й порядок розгортання

Спочатку застосуйте **тільки** `migrations/0004_catalog_107.sql` до окремої D1,
на яку вказує binding `DB` у **Preview**, потім розгорніть цю гілку в Preview.
Потрібні попередні міграції `0002_store_cart` і `0003_admin_telegram`.

1. Cloudflare → Workers & Pages → `loza-serhiia` → Settings → Bindings → **Preview**.
   Звірте назву та ID бази `DB` з Production: вони **мають відрізнятися**.
2. Відкрийте саме цю Preview D1 → Console. Виконайте файл `0004_catalog_107.sql`
   цілком. Не додавайте `BEGIN`/`COMMIT` у D1. Повторне виконання підтримується:
   ціни власника, підтвердження та залишки не скидаються.
3. Перевірте:

```sql
SELECT version FROM loza_store_migrations WHERE version='0004_catalog_107';
SELECT COUNT(*) AS real_varieties FROM product_catalog; -- 107
SELECT COUNT(*) AS pdf_prices FROM product_catalog
  WHERE json_extract(source_json,'$.priceKop') IS NOT NULL; -- 84
SELECT COUNT(*) AS kishmish FROM product_catalog
  WHERE json_extract(source_json,'$.details.kishmish')=1; -- 28
SELECT COUNT(*) AS archived_demos FROM products WHERE is_demo=1 AND available=0; -- 3
PRAGMA foreign_key_check; -- жодних рядків
```

Альтернатива для CLI: створіть локальний `.wrangler/catalog-preview.toml` із
фактичними **Preview** назвою/ID (плейсхолдери не є готовою конфігурацією):

```toml
name = "loza-catalog-preview-tools"
compatibility_date = "2026-10-22"
[[d1_databases]]
binding = "DB"
database_name = "<PREVIEW_DATABASE_NAME>"
database_id = "<PREVIEW_DATABASE_ID>"
```

```powershell
npx.cmd wrangler d1 execute DB --remote --config .wrangler/catalog-preview.toml --file migrations/0004_catalog_107.sql
```

Ця конфігурація лише для явного запуску D1-команди. Не використовуйте її для Pages
deployment і не змінюйте чинні binding/секрети. Вона ігнорується Git.

Нова міграція додає `product_catalog` і `catalog_imports`, змінює тільки тригер
редагування товару, додає перевірки ціни/каталогу перед покупкою. Не перебудовує
`orders`, `order_items`, `order_checkout`, `mono_events` та не змінює платежі,
Access чи Telegram. Новий код потребує міграцію 0004; не перемикайте його на базу
без міграції. Старий Preview після міграції вже не продаватиме архівовані демотовари.

**Production не мігрувати, не розгортати і PR не зливати без окремого підтвердження.**

## Редагування в адмінпанелі

У `/admin` → «Товари» → «Редагувати»:

1. Вкажіть дійсну ціну у гривнях або залиште поле порожнім.
2. Поставте «Підтверджую ціну для продажу». Зміна суми знімає прапорець.
3. Вкажіть фактичний доступний залишок і «Доступний для замовлення».
4. Після перевірки характеристик поставте відповідний прапорець.

Ціна підтверджується **для конкретної суми**. Зміна ціни без нового підтвердження
не дає купувати товар. API та SQL повторно перевіряють цей дозвіл; браузер не
визначає остаточну суму. Нульовий залишок виключає покупку навіть за старого кошика.

## CSV: заповнення всіх сортів

«Товари» → **«Завантажити CSV»**: актуальні дані 107 сортів із версіями записів,
UTF-8 BOM, роздільник `;`, десяткова крапка. Імпорт також приймає `,` як роздільник
і десяткову кому в правильно взятій у лапки клітинці. Не змінюйте заголовки та коди.
Працювати можна з усіма 107 рядками або з потрібною підмножиною.

| Колонка | Значення |
|---|---|
| `product_id`, `version` | Незмінний код і версія зі свіжого експорту |
| `name` | Назва, 2–160 символів |
| `price_uah` | Додатна ціна до 1 000 000 грн, до 2 знаків після коми; порожньо = без ціни |
| `price_confirmed` | 1 — власник підтвердив саме цю ціну, 0 — не підтверджено |
| `stock` | Цілий доступний залишок 0–1 000 000, з урахуванням резервів |
| `available` | 1 лише за підтвердженої ціни й залишку >0; інакше 0. Експорт показує фактичну доступність, зокрема 0 після вичерпання залишку |
| `taste`, `ripening`, `color` | Смак, дозрівання, колір з каталогу або перевірені власником |
| `kishmish` | 1 — кишмиш, 0 — без позначки; для PDF це не незалежна перевірка |
| `berry`, `shape`, `frost` | Вага ягід, форма, морозостійкість |
| `characteristics_confirmed` | 1 після перевірки власником; інакше 0 |

«Імпортувати CSV» → оберіть файл → **«Перевірити файл»** → перегляньте ціни,
залишки й доступність → **«Застосувати імпорт»**. До останньої дії записів немає.
Імпорт обмежений 107 товарами / 250 КБ. Він доступний тільки через Access JWT,
CSRF та same-origin JSON і підлягає обмеженню частоти адміністративних запитів.

Весь імпорт — одна атомарна SQL-операція з аудитом кожного товару. Якщо хоча б одна
версія застаріла (зокрема через новий резерв складу), нічого не зміниться. Повтор
того самого підтвердженого запиту не створює дубль. Після конфлікту завантажте
свіжий CSV й перенесіть правки; не підміняйте `version`, щоб обійти захист.

## Перевірка Preview

- `/api/products`: 107 реальних сортів, немає демотоварів/персональних даних/секретів.
- Каталог: немає фото, усі п'ять текстових характеристик + дозрівання; пошук за
  назвою, колір, термін дозрівання, діапазон ціни й кишмиш, скидання фільтрів.
- 23 початкові товари без ціни мають «Немає в наявності»; 84 PDF-ціни не вигадані.
- Без підтвердження або залишку кнопку купівлі вимкнено; прямий quote/create теж
  відхиляється. У локальних тестах є підтверджений товар для повного проходу кошика.
- CSV: попередній перегляд, зміна ціни/залишків, повтор запиту, застаріла версія,
  шкідливий текст і повний відкат імпорту. Не перевіряйте це на Production.
- `/admin`, `/api/admin/catalog/*` без дозволеного Access JWT недоступні; зміни
  без CSRF відхиляються. Дані покупців не входять в експорт.
- Старі замовлення й банківські події збережені; оплата залишається вимкненою.

Локальні тести використовують ізольовану D1, підписаний тестовий JWT, заглушки
Turnstile/Telegram та Edge на 1440, 390 і 320 px. Реальний бот не викликається.

```powershell
npx.cmd wrangler pages functions build --outfile .wrangler/admin-worker.js
# Потрібні Miniflare та Playwright; шляхи можна вказати через змінні нижче.
$env:LOZA_MINIFLARE_MODULE = "<absolute path to miniflare/dist/src/index.js>"
$env:LOZA_PLAYWRIGHT_MODULE = "<absolute path to playwright/index.mjs>"
node --test tests/access-configuration.test.mjs tests/admin-preview.test.mjs tests/catalog-csv.test.mjs tests/source-secrets.test.mjs tests/telegram-retry.test.mjs
```

Скриншоти й артефакти тестів записуються в `.wrangler`, не публікуються.
Публічні сторінки не містять платіжних полів і не вимагають monobank ключів.
