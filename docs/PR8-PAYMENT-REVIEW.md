# PR #8: перевірка ручного обліку оплати

23 жовтня 2026. База: PR #7. Production, реальні платежі та банківські секрети не змінювалися.

## Виправлення

- API відхиляє некоректні збережені умови/суми, застарілі версії й повторне встановлення того самого статусу. Підтвердження вимагає literal boolean true після окремого діалогу перевірки рахунку.
- Повтор прийнятого UUID не створює другу дію і не відновлює старий статус після подальшого виправлення. Конкурентні зміни проходять через атомарну перевірку версії SQL.
- Адмінпанель бере передоплату й післяплату з серверного розрахунку; некоректна сума не маскується нульовим залишком.
- Історія змін показує останні 100 платіжних дій: адміністратор, замовлення, час, версії, попередній і новий стан. Повний журнал зберігається в D1.
- Окрема додаткова міграція 0010 забороняє UPDATE/DELETE платіжного журналу. Встановлену вручну 0009 не переписано. Без позначки 0010 читання доступне, зміни оплати блокуються з 503.

## Локальна перевірка

Фінальний результат: 44/44 PASS, 0 FAIL, 0 skipped; Pages Worker збирається; git diff --check без помилок.

Справжній зібраний Pages Worker, ізольована Miniflare D1, RSA JWT fixtures; зовнішні API підмінено. Node 22.11.0, Wrangler 4.151.3, Miniflare 5.20261019.1-beta, Playwright / Microsoft Edge.

Перевіряються Access/JWT, CSRF/Origin, повторні та конкурентні запити, виправлення статусів, незмінність сум і checkout, повторний запуск 0009/0010, захист журналу, старі замовлення/банківські події, усі 107 сортів, CSV, Telegram, desktop/mobile, скасування діалогу підтвердження, довідники Нової пошти з mock API.
