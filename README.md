# LOZA — каталог і кошик на Cloudflare Pages

Поточний дизайн, головна сторінка, контакти та каталог збережені. Товари, ціни в копійках, наявність, склад і замовлення зберігаються в D1 через чинний binding `DB`. Платежі вимкнені.

## Перед публікацією

**Спочатку виконайте [D1-ROLLOUT.md](docs/D1-ROLLOUT.md), потім зливайте PR у main.** Готова адитивна міграція: [0002_store_cart.sql](migrations/0002_store_cart.sql). Автоматичної міграції чи зміни production binding під час збірки немає. Таблиці `orders` і `mono_events`, їхні записи, monobank webhook та банківські секрети збережені.

Потрібні нові змінні Cloudflare: `TURNSTILE_SITE_KEY` (публічна), `TURNSTILE_SECRET_KEY` (Secret), `CHECKOUT_SECURITY_KEY` (Secret). Якщо налаштування не завершені, оформлення блокується.

## Каталог і кошик

- Три демонстраційні товари з явно тестовими цінами та залишками; 107 наявних сортів імпортуються без реальних цін, недоступними для замовлення.
- `GET /api/products` повертає публічний каталог D1. Непрайсовані реальні сорти приховані до внесення актуальних даних.
- Додавання, видалення, кількість 1–5 кожного товару, до 20 різних товарів у кошику. Кошик зберігається в `localStorage`.
- Після зміни кошика `POST /api/cart/quote` рахує ціни рядків і загальну суму на сервері. Браузер тільки форматує отримані копійки у гривні, не підсумовує ціни.
- Оформлення запитує ім’я, телефон, місто, спосіб доставки, відділення та необов’язковий коментар. Номери/адреси відділень вводяться вручну; існуючий API довідника Нової пошти збережений.
- Після створення показуються номер, остаточна сума із D1 та «Очікує підтвердження» (`pending`).

## Новий API замовлення

`POST /api/orders/create`, `Content-Type: application/json`, заголовок `Idempotency-Key: <random UUID>`:

```json
{
  "items": [
    {"productId":"grape-demo","quantity":1},
    {"productId":"grape-demo-white","quantity":2}
  ],
  "customer": {"name":"Ім’я покупця","phone":"+380XXXXXXXXX"},
  "delivery": {"city":"Місто","method":"nova_poshta","branch":"Відділення №1"},
  "comment":"",
  "turnstileToken":"<свіжий токен віджета>"
}
```

Ціни, назви, статус і залишки з клієнтського payload не використовуються як джерело даних. Сервер перевіряє формат, довжини, телефон, кількість та дублікати товарів. Усі значення SQL передаються через `prepare().bind()`. Динамічно формується лише кількість знаків `?` для обмеженого списку товарів.

Збереження `orders` та `order_checkout` виконується D1 `batch`. Тригер нової таблиці перевіряє поточні залишки, створює позиції зі знімком назв/цін та резервує склад у тій самій транзакції. Помилка скасовує весь запис; повтор із тим самим ключем не списує залишок двічі. Підсумок SQL звіряється з сумою позицій. Ім’я, телефон та доставка зберігаються у приватній таблиці `order_checkout`, а не в публічному каталозі.

Нова відповідь містить `orderId`, `amountKop`, сумісне поле `amount` у гривнях, `currency`, `status`, `statusLabel`, `testOnly`, `paymentsEnabled: false`. Персональні дані у відповіді відсутні.

## Захист і повторні спроби

- Turnstile перевіряється сервером через Siteverify; додатково звіряються hostname та action `loza_checkout`. Перевірка не підміняється локальним прапорцем.
- Обмеження в D1 спільні для всіх інстансів: 8 створень/хв, 90 розрахунків/хв і 30 перевірок квитанції/хв на IP, за фіксованими хвилинними вікнами. Відповідь 429 містить `Retry-After`.
- У таблиці rate limit зберігається HMAC від IP та призначення запиту, а не IP. Старі вікна очищуються фоново під час нових запитів.
- Повторний ключ прив’язаний до нормалізованого складу кошика та даних оформлення. Зміна даних після створення дає 409.
- У `sessionStorage` є лише приватний випадковий ключ і IDs/кількість товарів. Ім’я, телефон і доставка там не зберігаються. Після невизначеної відповіді їхній знімок утримується лише в пам’яті вкладки до повтору/закриття.
- `POST /api/orders/receipt` із тим самим приватним ключем дозволяє відновити номер/суму/статус після перезавантаження; особистих даних не повертає. При 404 ключ зберігається для безпечної повторної відправки.
- API не видає внутрішні SQL помилки, не має GET зі списком замовлень, не відкриває CORS для сторонніх сайтів, перевіряє Origin у POST та обмежує тіло 16 КБ. Секрети не записуються у відповіді або браузерні ресурси.

## Сумісність наявних адрес

`/api/order` залишається як адреса, але тепер використовує той самий захищений JSON-контракт нового API; старий multipart-переказ із чеком вимкнений разом із платежами. Це закриває альтернативний шлях обходу Turnstile та серверних цін. `/order-demo` перенаправляє в актуальний каталог/кошик. Файли `functions/api/mono/*`, `functions/api/np.js`, `functions/api/db-test.js` та `_routes.json` не змінюються. Прямі повідомлення Сергію через контакти залишаються доступними.

## Основні файли

- `index.html`, `storefront.css`, `storefront.js` — чинний дизайн і новий кошик.
- `server/checkout.js` — нормалізація, квоти, Turnstile, котирування й приватне підтвердження.
- `functions/api/products.js`, `functions/api/store/config.js`, `functions/api/cart/quote.js`, `functions/api/orders/*` — Pages Functions.
- `migrations/0002_store_cart.sql` — схеми й початкові товари.
- `docs/D1-ROLLOUT.md` — точні команди застосування, резервної копії та налаштування.

Резервні копії живої D1 зберігайте поза цим репозиторієм і папкою публікації. `node_modules`, локальні секрети й `.wrangler` ігноруються Git.
